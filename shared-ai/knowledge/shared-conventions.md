# Claude Code / Codex 共通規約

## 知識の扱い

- 生資料、AIが統合したWiki、運用Schemaを区別する。
- 生資料は書き換えず、Wikiへ反映するときは出典を残す。
- AI生成ノートは候補であり、人間の有用性評価と案件結果なしに判断資産へ自動昇格させない。
- RAGは廃止せず、promoted knowledgeと統合済みWikiを優先して検索する。

## 実行資産の扱い

- 共通Skillの正本は `shared-ai/skills/` とし、ツール別ディレクトリへコピーしない。
- Skillは1責任に絞り、必須でない手順・将来用の雛形・固定文字数基準を増やさない。
- 外部由来のSkillは、指示・スクリプト・外部通信・ファイルアクセスを監査してから導入する。
- MCPとCLIは二者択一にせず、権限、対話性、出力量、再現性の実測で選ぶ。

## Jev / TypeSafe の安全な常用

Reason: Jevへ内部実装の説明を直接送ると外部送信審査で止まりやすい一方、使わないと分類・選別を推論モデルへ寄せすぎる。
Scope: Claude CodeとCodexが、このリポジトリで分類、フィルタリング、ルーティング、ランキング、その他の限定判断を行う時。
Retirement: Jev MCPがローカル判定になり、またはハーネスが安全なstate投影を自動保証するようになった時。

- 限定判断がある時はJevを優先する。複雑な原因分析、設計、実装順序、不可逆操作の決定はCodex/Claude側に残す。
- Jevへ渡す前に、対象を安全な投影へ変換する。IDは `item_1` のような合成ID、本文は「既存画面へフィードバック操作を追加」のような一般機能説明にする。
- 安全な投影に含めてよいのは、成果物種別、一般化した変更効果、依頼との関係、公開情報、閉じた選択肢と判定基準だけとする。
- ファイル名・パス、リポジトリ名、シンボル名、コード、diff、ログ、テスト出力、内部アーキテクチャ、Vault本文、案件情報、個人情報、秘密情報は送らない。
- コードが実候補を集め、Jevには意味判定だけを依頼し、返ったIDをローカルで元候補へ対応付ける。Jevにファイル操作やworkflow制御を任せない。
- 安全な投影では根拠が失われて判定不能になる場合、そのステップだけローカル推論へ戻す。Jevを通すために情報量を増やさない。
- 原則として top probability または confidence が0.7未満なら自動採用せず、Codex/Claudeが判断する。
- どのステップでJevを使ったか、使えなかった場合はその理由を最終報告へ明記する。
- 定型の投影には `scripts/jev_safe_gateway_cli.py` を使える。入力は `abstract`（内部成果物の一般化）、`aggregate`（案件・業務データのカテゴリ化）、`public_excerpt`（公開URLで検証できる短い公開コード）の3モードとする。
- Gatewayの `status` が `allowed` の時だけ `outbound` をJevへ渡す。`local_mapping` と監査記録はローカル専用で、Jevへ送らない。
- `public_excerpt` は公開物だけの例外である。私有コード・diff・ログを公開扱いに偽装して送らない。

## ツール固有規約との境界

- sandbox、権限、hooks、モデル選択、プラグイン設定は各ツール側の司令塔へ残す。
- 共通規約とツール固有規約が衝突した場合は、より具体的で現在の実行環境に近い規約を優先する。
