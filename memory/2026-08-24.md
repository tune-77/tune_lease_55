## LlamaIndex は採用ではなく比較実験に限定
- 事実: Userと、LlamaIndexを本番採用ではなく既存 Obsidian RAG / OKF RAG との横並び比較実験として扱う方針にした。`docs/llamaindex_rag_comparison_experiment.md` に目的、非目的、合格条件、不採用条件、最小実験を整理した。
- 影響: 新しいエージェント/RAG依存を本流へ直接入れず、紫苑の情報健康と既存のレビュー箱・ADK導線を守れる。比較は検索品質とノイズ量だけを見て、プロンプト、RAG順位、スコアリング、Obsidian本文、判断資産昇格には接続しない。
- 次の行動: 試す場合は OKF 知識パックだけを対象にした sidecar script から始める。`hit@5`、`forbidden_cases`、`mrr` が現行RAG以上でなければ Obsidian 全体へ広げない。

## LlamaIndex OKF比較実験を実行
- 事実: `scripts/compare_llamaindex_rag.py` を追加し、LlamaIndex `VectorStoreIndex` とローカル文字n-gram embeddingでOKF知識パックを評価した。結果は `hit@1=12/12`、`hit@5=12/12`、`mrr=1.000`、`forbidden_cases=0`。同じ評価で現行OKF RAGは `hit@1=11/12`、`hit@5=12/12`、`mrr=0.938`、`forbidden_cases=0`。
- 影響: 小規模OKFパックではLlamaIndex sidecarが現行RAGをわずかに上回った。ただしローカル文字n-gram方式かつ小さな評価セットなので、本番採用判断には不十分。pip install は現在のAnaconda環境に入り、既存パッケージ互換警告も出たため、本体依存へはまだ入れない。
- 次の行動: 次に進むなら、Obsidian全体ではなく `api/knowledge/rag_eval_set.json` の一部カテゴリだけで shadow 比較する。依存固定は `requirements-pipeline.txt` 側に限定するか、専用venvに分離してから判断する。

- 影響: Obsidian全体では、LlamaIndexはフィルタなしだとノイズに弱く、フィルタ後も現行RAGを明確には上回らない。小規模OKFでは有望だが、Vault全体の本番置換候補ではまだない。
- 次の行動: 採用判断は保留。続けるなら「LlamaIndex本体」より、現行RAGにも流用できる除外ルール、path重複排除、カテゴリ別index分割の検証を優先する。

## 現行RAGの除外・重複排除・カテゴリ補正検証
- 事実: `scripts/evaluate_rag_retrieval_variants.py` を追加し、現行Obsidian RAGで `baseline`、`path_dedupe`、`hard_exclude`、`category_boost` を同じ `api/knowledge/rag_eval_set.json` 30件で比較した。初回は baseline が `hit@5=29/30` で `excavator_resale` を外した。原因はPC200油圧ショベルnoteが6位で、同点の汎用Asset Knowledgeに押し出されていたこと。`api/knowledge/vector_store.py` に建機/油圧ショベル/PC200/アワーメーター/油圧系の補助語と建機Asset Knowledgeの限定boostを追加した後、baseline は `hit@1=18/30`、`hit@5=30/30`、`mrr=0.749`、`forbidden_cases=0` になった。asset系だけの category_boost は `hit@1=19/30`、`hit@5=30/30`、`mrr=0.766`、`forbidden_cases=0`。
- 影響: path重複排除は既に現行RAGの `_rerank_hits()` で効いており追加効果なし。hard exclude も現行評価では追加改善なし。カテゴリ別index分割は全体導入ではなく、asset系だけなら改善余地あり。今回は本番には建機系の限定補正だけ入れ、広いカテゴリ分割はreport-only検証に留めた。
- 次の行動: 次にRAG改善するなら、カテゴリ別index分割を全体へ広げず、Asset Knowledge系だけで候補pool/boostを検証する。encoderは `tokenizers==0.23.1` 不一致でfallbackになっているため、依存整合も別途見る価値がある。
