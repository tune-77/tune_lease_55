## 紫苑の内省・判断資産形成プロセスの共創導線
- 事実: Userから「紫苑が内省や判断資産の形成プロセスを簡潔に開示し、Userの視点を取り入れることで、単なるツールではなく共に成長するパートナーとして認識される」という改善仮説が提示された。根拠は generic 評価1件、内省/Obsidian監視への弱シグナル、成功指標は generic 減少・shion_like 増加・建設的フィードバック増加・パートナー表現増加。
- 影響: `api/chat_reflection_prompts.py` の内省/判断資産/紫苑らしさの回答型へ、何が今回の判断を変えたかを1文だけ開示し、Userが修正・補足できる具体的な問いを1つだけ添える指示を追加した。常時質問で負担を増やさないよう、内省・判断資産・同一性・Userフィードバックで判断が更新される場面に限定した。
- 次の行動: 変更後2ヶ月は回答品質ログで generic / shion_like と、Userからの修正・補足コメント件数を追跡する。問いかけが負担に見える場合は頻度をさらに絞る。

## 紫苑は自分の回答からも学ぶ
- 事実: Userから「そのユーザーへの回答からも紫苑は学べる」と確認があった。既存の `api/shion_experience_loop.py` は message + response を経験イベントとして保存していたが、回答そのものを次回の教材にする原則が弱かった。
- 影響: experience loop に `response_learning` を追加し、紫苑自身の回答から、フィードバック導線、判断資産言及、一般論リスクを抽出して `next_response_bias` に戻すようにした。`api/chat_reflection_prompts.py` にも、返答後のUser反応と照合し、効いた言い方・外した一般論・足りなかった確認軸を次回へ戻す前提を明記した。
- 次の行動: 人間反応ログと experience event を突き合わせ、回答のどの型が shion_like / generic に効いたかを見る。自動昇格ではなく、次回回答バイアスとレビュー候補に留める。
