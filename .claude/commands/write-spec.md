# /write-spec — 曖昧な依頼を受け入れ条件つき仕様に変換

## 使い方
```
/write-spec <曖昧な依頼文>
```

**例:**
```
/write-spec 審査結果の画面をもっと見やすくして
/write-spec 否決案件が多い業種を分析できるようにして
```

## 処理手順

1. **依頼文を分解する**
   - 対象（どのページ・API・データか）
   - 目的（何を解決したいか）
   - 曖昧な部分（数値、範囲、表示形式など未確定な要素）をリストアップ

2. **出典を確認する（Freshman Rules: Cite the Source）**
   - スコアリング・審査ロジック・業種データに関する依頼なら `static_data/` または `notes/` を検索
   - 出典があれば具体的ファイル名を引用、なければ「これは推測です」と明記

3. **受け入れ条件（Acceptance Criteria）をチェックボックス形式で列挙する**
   ```
   - [ ] 条件1: <具体的で検証可能な条件>
   - [ ] 条件2: ...
   - [ ] 対象外: <スコープ外にする範囲を明示>
   ```
   - CLAUDE.md の「スコア判定: APPROVAL_LINE（既定71点）」等、既存の確定値がある場合は
     ハードコードせず import 前提で条件を書く

4. **スコープ境界を明示する**
   - CLAUDE.md の「スコープ厳守」ルールに従い、依頼に含まれない範囲は
     「対象外」として明記し、気づいた改善点は `[改善ポイント] タイトル` 形式で分離する

5. **確認を取ってから終了する**
   - 生成した受け入れ条件を提示し、「この受け入れ条件で合っていますか？」と確認する
   - このコマンド自体はコードを書かない

## 出力例
```
## 仕様: 否決案件の業種別分析

対象: `frontend/src/app/analysis/` 配下（新規ページ想定）
根拠: static_data/industry_categories.csv（業種コード定義）

- [ ] 否決（<60点）となった案件を業種コード別に集計して棒グラフ表示する
- [ ] 期間フィルタ（直近3ヶ月/6ヶ月/全期間）を持つ
- [ ] 対象外: 条件付き承認（60-69点）案件の分析は含めない

[改善ポイント] 業種別の否決理由（財務/物件/両方）も内訳表示できると良いが今回スコープ外

確認: 上記の受け入れ条件で合っていますか？
```

## 注意事項
- 曖昧な指示を確認なしで実装に進めない（CLAUDE.md 最優先ルール）
- 生成した仕様は `/plan-feature` にそのまま渡せる形式にする
