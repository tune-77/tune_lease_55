# /update-docs — 変更に合わせたドキュメント更新

## 使い方
```
/update-docs [対象範囲: readme | claude-md | worklog | all（省略時 all）]
```

## 処理手順

1. **直近の変更内容を把握する**
   - `git diff master --stat`（または直近コミット）で変更ファイル一覧を取得
   - `/explain-diff` の出力があればそれを再利用する

2. **README.md / README.en.md の更新（対象: readme, all）**
   - 新規エンドポイント・新規ページ・新規コマンドを追加した場合のみ該当セクションを更新
   - 既存の説明と矛盾する記述がないか確認
   - 日本語版を更新したら英語版 `README.en.md` にも同内容を反映する（ズレ防止）

3. **CLAUDE.md「要注意領域」表の更新（対象: claude-md, all）**
   - 新しく事故が起きやすい/注意が必要なファイル・領域を追加した場合のみ表に1行追加する
   - 既存ルール（絶対禁止・スコープ厳守等）と矛盾する変更は提案しない
   - 変更は追記または該当行の更新のみ。無関係な既存ルールは書き換えない

4. **Work Log ドラフトを生成する（対象: worklog, all）**
   - Work Logs の実体は `~/Library/Mobile Documents/iCloud~md~obsidian/.../Work Logs/` にあり、
     このセッションからは直接書き込めないため、**貼り付け用ドラフトをチャットに出力するのみ**とする
   - フォーマット:
     ```markdown
     ## <YYYY-MM-DD> <変更タイトル>
     - 変更内容: ...
     - 対象ファイル: ...
     - 動機・背景: ...
     - 注意点（次回このファイルを触る人へ）: ...
     ```
   - `WEEKLY_LOG.md` には追記しない（`scripts/weekly_self_management.py` が自動生成する専用ファイルのため）

5. **完了確認**
   - 更新したファイルの差分を提示し、意図しない箇所を書き換えていないか確認を促す

## 注意事項
- `data/` 配下・`.streamlit/secrets.toml` には触れない
- Work Logs vault へは書き込まない（ドラフト提示のみ、ユーザーが手動で貼り付ける）
- ドキュメント更新はスコープを超えない（依頼された変更に関係する記述のみ更新する）
