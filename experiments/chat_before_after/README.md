# 紫苑チャット 今週の変更 前後比較（2026-10-03）

今週（PR #1190〜#1223）の変更で、紫苑の通常チャット（`/api/chat`, response_mode=shion。直近の利用の9割）の答えがどう変わったかを、同じ10問で比べる実験。

## やり方
- **前**: master `3ac81b0`（#1190 の直前、2026-10-01 07:00 以前）を別 worktree で起動（ポート 8101）。
  データは当時の追跡ファイル＋ iCloud の `case_data_20260927_013000`（平文・9/27）で上書き。教えたノウハウ（chat_judgment_teaching）0件、記憶索引 524件
- **後**: 今の master `c144700` を別 worktree で起動（ポート 8102）。データはメインの作業データのコピー。教えたノウハウ 82件、記憶索引 623件
- 本番の API（127.0.0.1:8000）・メインチェックアウト・本番データには触れていない（worktree と APFS クローンのコピーだけに書き込み）
- `server.py` は副作用だけ止める（Obsidian 自動保存の判定・DB の git push・Slack 環境変数）。Gemini の鍵は本番と同じく api.main が設定ファイルから読む（このスクリプトは鍵を扱わない）
- 採点は `compare.py` の機械的なキーワード判定のみ（LLM の自己採点は使わない）

## 限界（結果を読むときの注意）
- **Vault と ChromaDB は前後とも今のもののコピー**。週次の Obsidian バックアップが 9/20・9/27 とも空（iCloud の未ダウンロードファイルで失敗）で、当時の Vault が無かったため。差は「コード＋data/（教えたノウハウ・判断資産・記憶索引・DB）」に限られる
- Gemini 呼び出しは 1問あたり2回（計40回）で、目標の約20回を超えた
- キーワード判定は言い換えに弱い。結果を見た後にキーワードを足すことはしていない（「リサイクル」「見積」単独は一般回答にも出るため外しただけ）
- 機械判定の見落とし（目視で確認）:
  - Q9 残価保証: 前は「リース会社が保証」、後は「借手が保証」。会計上は借手（または第三者）による保証で、**後が正しく前は誤り**だが、キーワード判定は両方○
  - Q5 3月・9月: 後は「メーカー側の決算目標に向けた営業攻勢」に触れており、教えた「サプライヤーの売り込み」に近いが、キーワード判定は×
  - Q4 銀行取引なし: 後も「付き合わない」という教えた方針は使っておらず、高リスクとして確認を促すに留まる（本当の取りこぼし）
