# 判断資産の同一性判定に Jev は効くか（2026-10-02）

週次の重複整理（`scripts/judgment_asset_dedup.py`）で、2件が「同じ判断資産として統合してよいか」を
Jev に二値で聞く価値があるかを、実データで測った。

## データ

- 正解: 2026-10-02 の人手統合（17クラスタ・28件、111→83件）。
  - 同じクラスタ内のペア = 統合してよい（正例）
  - 統合前スナップショットで類似度上位だが統合しなかったペア = 違う（負例）。
    埋め込み上位30と文字bigram上位30の和集合から取り、片方の指標に有利な選び方を避けた。
- 外部送信前に `typesafe_dedup_guard.is_safe_public_candidate` で社名・人名等を含むペアを除外。
- 94ペア（正例39 / 負例55）。統合時に Jev へ相談した境界ペアを除いた82ペアでも集計（ラベル漏洩の感度分析）。

## 結果

| 指標 | AUC（全94） | 95% CI | AUC（相談ペア除外82） | Brier（生） | Brier（LOO Platt） |
|---|---|---|---|---|---|
| Jev（同じ判断資産か） | **0.857** | 0.773–0.922 | 0.867 | 0.168 | 0.187 |
| 埋め込み類似度 | 0.495 | 0.375–0.610 | 0.506 | – | 0.249 |
| 文字bigram一致 | 0.462 | 0.338–0.587 | 0.466 | – | 0.249 |

- 埋め込み・文字一致が 0.5 前後なのは、負例を「似ているのに統合しなかったペア」で選んだため（構造上不利）。
  ただし週次で Jev に聞くのはまさに「似ているペアの中の見分け」なので、比較として妥当。
- Platt 補正で Brier は改善しなかった（0.168→0.187）。確率は生値のまま「並び順・目安」として表示する。
- Jev の取りこぼしは「確認質問／リスク兆候／判断ルール」の三つ組（例: 更新計画の質問 と 老朽化放置のリスク）。
  人手統合でも最も踏み込んだ統合で、Jev の慎重さは妥当な範囲。

## 運用への反映

- 閾値 0.2 未満の候補を落とす: 正例 39/39 を残し、負例 21/55 を落とせた。
- 自動統合には使わない（正規化後に同文のものだけ決定的ルールで自動統合）。
- 候補の前段は固定閾値（文字0.30/埋込0.75）だと正例 4/39 しか拾えず、各資産の近傍上位3件（埋込・文字それぞれ）で 35/43。
- 判定は `jev_judgment_log.jsonl`（REV-424）に guard=`judgment_asset_dedup` で記録する（本文はハッシュのみ）。
