# Shion Memory Layers

紫苑の記憶は、寿命と役割で分ける。目的は「たくさん覚える」ことではなく、現在の回答に必要な記憶だけを適切な強さで使うこと。

## Layers

- short_term: 現在の会話、現在案件、直近のツール結果。セッション状態やプロンプト内文脈で扱い、永続保存しない。
- mid_term: 数日から数週間の作業流れ、日次ログ、改善ログ、自己提案ログ。主な保存先は `memory/YYYY-MM-DD.md` と reports/data 系ログ。
- long_term: 繰り返し確認された判断軸、ユーザー方針、再利用可能な教訓。主な保存先は `MEMORY.md`。
- persistent: 人格、運用原則、安全境界、記憶昇格ルール、判断資産システムの設計思想。保存先は `PERSISTENT_MEMORY.md`。
- retrieval: Obsidian、案件DB、過去審査、FAQ、ナレッジベース。必要時に検索して使う。

## Promotion Policy

- short_term から mid_term: 作業結果、ユーザーの明示方針、後で追跡すべき判断が出た時。
- mid_term から long_term: 同種の課題が3回以上出た時、今後の意思決定に影響する方針変更があった時、再発防止すべき失敗があった時。
- long_term から persistent: 個別案件や一時的好みを超え、紫苑の運用原則として残すべき時。
- retrieval は原資料であり、昇格候補ではあるが、根拠確認なしに長期・永続へ直接入れない。

## Guardrails

- 古い記憶は、現在の事実やユーザーの最新指示と衝突したら弱める。
- 個人記憶は本人との会話でのみ使う。
- 永続記憶は強いが、ユーザーの明示指示、安全、法令、実データに優先しない。
- 記憶を使った時は、必要に応じて「以前のどの判断軸が効いているか」を短く示す。
