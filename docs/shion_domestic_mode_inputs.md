# 紫苑 内政モード入力メモ

紫苑の自己提案は、改善案を増やすためではなく、システム内部の導線・情報配置・記憶運用・改善候補を見回し、削る・移す・残す・測るを判定するために使う。

## Userが与えると効く情報

- 重要度: 低利用でも残すべき画面・機能・知識か。
- 使用文脈: いつ、どの画面や業務の途中で必要になるか。
- 意図: その機能を何のために置いているか。審査、営業説明、記憶整理、デモ、監査など。
- 判断基準: 削除、統合、再配置、観測継続をどう分けるか。
- 禁止線: 自動で削らないもの、外に出さない情報、触ると危ない導線。
- 成功指標: 利用回数、遷移率、評価コメント、作業時間、再質問減少など何で効いたと見るか。
- 観測期間: 7日、30日、発表後、月次など、いつ再判定するか。
- 作業録要約: Codex/Claudeが何を実装・検証し、Userが何を採用/保留したか。

## 紫苑の判定ラベル

- 価値不足: 目的自体が薄い、または他機能で十分代替できる。
- 発見性不足: 価値はあるが見つからない。
- 文脈不足: 価値はあるが必要な作業の途中に出ていない。
- 削除候補: 残す理由が弱く、代替導線もある。
- 再配置候補: 必要な画面や会話の近くへ移す。
- 観測継続: 情報が足りないため、今は削らず測る。

## 遺伝的ループ

内政モードでは、自己提案を固定ルールではなく「判断仮説の個体」として扱う。

- 選択: Userの採用 / 保留 / 却下。
- 適応度: 成功指標、根拠、リスク記載、採用状態から計算する `fitness_score`。
- 突然変異率: 次回どれくらい違う方向へ提案するかを示す `mutation_rate`。
- 継承方針: 採用系統は小さく改善し、却下系統は抑制または別方向へ変異し、保留系統は追加根拠を求める。
- 跳躍提案: 最大1件だけ許可する。面白さだけではなく、測れる違和感として `success_metric` と `risk` を必ず持たせる。


## 運用

紫苑はこの情報を、ログ由来の自己提案より優先して扱う。ただし人間の意図も固定正解ではなく、利用ログ・反応・検証結果と矛盾した場合は、変更理由を添えて再提案する。

Codex/Claude作業録は全文ではなく、`Summary / Chat Summary / Decisions / Changes / Verification / Open Items` だけを短く渡す。これはUserの思考・選択圧・実装制約を知るための補助情報であり、顧客情報の推測、Private Reflection原文引用、人間承認なしの判断資産昇格には使わない。
