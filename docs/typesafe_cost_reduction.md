# TypeSafe/Jev コスト削減構成

更新日: 2026-09-20

## 実装済みの置換

| 処理 | Jevの役割 | Geminiの扱い | 停止方法 |
|---|---|---|---|
| チャット質問分類 | 4カテゴリChoice | 低信頼・障害・機密入力だけフォールバック | `TYPESAFE_ROUTING_MODE=off` |
| RAG候補判定 | 関連・根拠・矛盾・注入判定 | 最終回答生成だけ継続 | `TYPESAFE_RAG_ENABLED=0` |
| 改善候補トリアージ | today/later/discard Choice | Jev障害時だけフォールバック | `TYPESAFE_TRIAGE_MODE=off` |
| 改善候補の意味重複 | 灰色帯ペアのNoul | 15件超の統合文章だけ継続 | `TYPESAFE_DEDUP_ENABLED=0` |
| 改善レシピ判定 | auto/discuss/review Choice | 低信頼・障害時だけフォールバック | `TYPESAFE_RECIPE_CLASSIFY_ENABLED=0` |
| Obsidianエンティティ整合（明示実行のみ） | 関連・重複判定 | 自動統合には使わない | `TYPESAFE_OBSIDIAN_ALIGNMENT_ENABLED=0` |

チャットの `shion_query_class` ログは、既に計算済みの質問カテゴリからコードで
決定する。以前のようにログ用途だけでGeminiを再呼び出さない。

## 外部送信しないもの

- 個別審査、企業名、案件番号、顧客番号、財務・金額、氏名、住所、電話、メール
- Obsidian本文、絶対パス、Vault内相対パス
- 数値計算、スコアリング、回帰分析の入力

上記を検出した場合はローカル処理またはGeminiの既存経路へ戻す。TypeSafe障害時も
既存処理へfail-openし、自動承認や審査結論をJev単独では変更しない。

## 実測

- チャット分類4件: すべて期待カテゴリ、confidence 1.0、入力1,723 / 出力232 tokens
- 改善レシピ3件: auto 0.97 / discuss 0.98 / review 1.0、入力1,305 / 出力127 tokens
- 意味重複28ペア: 1リクエスト、入力7,581 / 出力554 tokens、高信頼重複6ペア
- 改善トリアージ: 1リクエストに最大12候補をまとめる

## Jevへ置換しない処理

次は選択・判定ではなく新しい文章やデータの生成が必要なため、生成モデルまたは
決定的コードに残す。

- ユーザー向け最終回答、説明、要約、内省、改善案の新規発案
- Web検索と検索結果の文章統合
- OCR、表抽出、自由形式のトピック名・本文生成
- 統計計算、スコアリング、回帰分析

この境界により、Jevを安価な判断プリミティブとして使いつつ、生成品質と数値処理の
再現性を維持する。
