# Vertex AI Search Obsidian Pilot

## Purpose

Use the remaining Gen AI App Builder / Vertex AI Search credits to evaluate
Google-managed search and summary quality against the tune_lease_55 Obsidian
lease knowledge corpus.

This is a pilot path only. It does not replace the existing local Obsidian RAG
or production chat route.

## Corpus

Local export path:

```bash
data/agent_search/lease_knowledge_export/
```

Generated by:

```bash
python3 scripts/export_obsidian_for_agent_search.py --max-docs 180
```

The exporter intentionally excludes chat logs, daily memory, private reflection,
Cloud Run conversation logs, raw feedback return files, and secret-like files.
It also applies a pre-Vertex quality gate:

- Adds `canonical_topic`, `source_bucket`, and `quality_score` to each exported
  document
- Deduplicates notes by `canonical_topic` before upload
- Excludes explicit private markers such as `public: false`,
  `vertex_exclude: true`, `visibility: private`, and confidential notes
- Excludes operational or identity/value-layer notes such as Mana logs,
  hackathon plans, Claude/CSS implementation notes, Judgment Asset OS docs, and
  raw inbox material
- Rejects thin keyword-only notes that do not contain enough reusable screening
  judgment, confirmation points, risk conditions, sources, or update triggers

Current pilot corpus:

- 118 Obsidian-derived text documents
- Source folders: selected `Projects/tune_lease_55/Research` and
  `Projects/tune_lease_55/Judgment Assets`
- Search app created with `SEARCH_TIER_ENTERPRISE` and `SEARCH_ADD_ON_LLM`

## Automated Obsidian Sync

Use this script to refresh the Vertex AI Search corpus from the normal iCloud
Obsidian Vault:

```bash
python3 scripts/sync_obsidian_to_vertex_agent_search.py --upload --import-documents --wait
```

Safer local dry run:

```bash
python3 scripts/sync_obsidian_to_vertex_agent_search.py --upload --import-documents --dry-run
```

What it does:

- Exports selected lease knowledge notes with the same privacy filters as the
  pilot exporter
- Computes an export signature and skips cloud sync/import when the Obsidian
  corpus did not change
- Writes `manifest.json`, `documents.jsonl`, and text files under
  `data/agent_search/lease_knowledge_export/`
- Syncs the export folder to
  `gs://tune-lease-55-data/agent-search/lease-knowledge/`
- Calls Discovery Engine `documents:import` against
  `tune-lease-55-obsidian-lease`
- Writes a run report to `reports/vertex_obsidian_sync_latest.json`
- Stores the last uploaded signature in
  `data/agent_search/vertex_obsidian_sync_state.json`

Nightly pipeline wiring:

- `scripts/run_daily_improvement_post.sh`
- Step name in `data/pipeline_step_log.jsonl`:
  `sync_obsidian_to_vertex_agent_search`
- Runs after the existing public-note GCS upload and only after Mana allows the
  post pipeline to continue
- Use `--force` manually if a re-import is needed even when the exported corpus
  signature is unchanged

Stale GCS cleanup is intentionally opt-in:

```bash
python3 scripts/sync_obsidian_to_vertex_agent_search.py \
  --upload --delete-stale-gcs --import-documents --wait
```

Default import mode is `INCREMENTAL`. Use `--reconciliation-mode FULL` only
when intentionally replacing the full data store contents.

## Hybrid Chat Wiring

The normal chat RAG path now keeps existing local Obsidian RAG as the primary
source and appends Vertex AI Search only as supplementary context.

- Module: `api/vertex_agent_search.py`
- Chat integration point: `api/main.py` `next_chat_rag`
- Response metadata: `vertex_ai_search`
- Debug metadata: `memory_debug.vertex_ai_search`

Default behavior:

- `VERTEX_AGENT_SEARCH_ENABLED` defaults to enabled.
- If auth, network, or config fails, the module returns a skipped/error payload
  and the existing Obsidian RAG path continues.
- Vertex results are deduplicated by canonical topic/source path to avoid
  repeated Auto Research notes dominating the prompt.

Useful environment variables:

```bash
VERTEX_AGENT_SEARCH_ENABLED=true
VERTEX_AI_SEARCH_PROJECT_ID=gen-lang-client-0420497423
VERTEX_AI_SEARCH_ENGINE_ID=tune-lease-55-obsidian-search
VERTEX_AI_SEARCH_LOCATION=global
VERTEX_AI_SEARCH_COLLECTION=default_collection
VERTEX_AI_SEARCH_PAGE_SIZE=3
VERTEX_AI_SEARCH_TIMEOUT_SECONDS=8
```

Fast rollback:

```bash
VERTEX_AGENT_SEARCH_ENABLED=false
```

## Extended Vertex Options

Implemented the five follow-up options from the pilot:

1. Answer API comparison
2. Search controls for boost/bury/filter experiments
3. Google Search grounding for latest public-web checks
4. Debug UI for Vertex knowledge search
5. Widget/embed configuration check

### API endpoints

```bash
POST /api/vertex-search/debug
POST /api/vertex-search/workflow
POST /api/vertex-search/external-grounding
GET  /api/vertex-search/widget-config
```

`/api/vertex-search/workflow` is the practical usage endpoint. It keeps Vertex
as a supplementary index and restricts usage to three modes:

```json
{
  "topic": "補助金前提の工作機械リース",
  "mode": "evidence_support",
  "page_size": 5,
  "save_to_obsidian": true
}
```

Modes:

- `evidence_support`: find source notes and grounded hints for screening
  comments
- `judgment_candidates`: find confirmation-question / approval-condition /
  counterpoint candidates, without auto-promoting them
- `knowledge_audit`: check topic duplication, weak coverage, stale areas, and
  next notes to curate

All workflow responses include a guardrail: Vertex is a supplementary index;
Local RAG, Obsidian source notes, and human review remain the primary judgment
path.

When `save_to_obsidian` is true, the workflow result is stored in the normal
iCloud Obsidian Vault under:

```text
Projects/tune_lease_55/Research/Vertex Distilled/
```

Saved notes include the workflow mode, query, Answer API summary, high-signal
search hits, refs, next actions, grounding metadata, and a `needs_human_review`
frontmatter flag. They are deduplicated by workflow mode + query and are not
auto-promoted into judgment assets.

Batch material collection while Vertex credits are available:

```bash
python3 scripts/collect_vertex_workflow_materials.py \
  --limit 8 \
  --modes evidence_support judgment_candidates knowledge_audit \
  --page-size 5
```

This writes bounded workflow notes to `Vertex Distilled/` and a local run report
to `reports/vertex_workflow_materials_latest.json`. Use `--dry-run` before a
larger run, and tune `--limit` / `--modes` to avoid collecting low-value noise.

## Research Mode Integration

Chat external Research mode now pairs the normal Auto Research note with Vertex
material capture for the same topic. When the user explicitly allows external
research, the app:

- writes the normal web/Auto Research note under
  `Projects/tune_lease_55/Research/Auto Research/`
- captures Vertex workflow material for `evidence_support` and
  `judgment_candidates`
- saves those Vertex material notes under
  `Projects/tune_lease_55/Research/Vertex Distilled/`
- adds the saved Vertex note refs to the research prompt context

This integration is best-effort: Vertex capture failure does not break the
normal Research answer path. Set `VERTEX_RESEARCH_MATERIAL_CAPTURE_ENABLED=false`
to disable the paired Vertex capture.

`/api/vertex-search/debug` can run Search API, Answer API, and Google Search
grounding on the same query:

```json
{
  "query": "補助金前提の工作機械リースで確認すべきこと",
  "page_size": 3,
  "include_search": true,
  "include_answer": true,
  "include_google_grounding": false
}
```

`/api/vertex-search/external-grounding` returns the custom search API shape that
Gemini grounding can consume:

```json
[
  {"snippet": "...", "uri": "..."}
]
```

If exposing this endpoint outside the local app, set
`VERTEX_SEARCH_EXTERNAL_API_KEY` and send it as `X-Vertex-Search-Key`.

### Answer API grounding support score

Answer API calls use `v1beta` and send:

```json
{
  "groundingSpec": {
    "includeGroundingSupports": true
  }
}
```

If Vertex returns official `groundingScore` / `groundingSupports`, the app
uses those values directly. In the current Obsidian Data Store verification,
Vertex returned citations but no `groundingSupports`, so the app exposes a
fallback `grounding_score` based on cited answer-span coverage and marks it
with:

```json
{"grounding_score_source": "citation_coverage_fallback"}
```

Verified query:

```text
工作機械 補助金 リース料軽減 公募要領 対象経費 Q_risk 確認論点
```

Observed result:

- `grounding_score`: `0.887`
- `grounding_score_source`: `citation_coverage_fallback`
- `support_count`: `25`
- `low_support_claim_count`: `0`

### Search controls

Default search controls are local reranking hints rather than permanent
Discovery Engine data-store mutations. This keeps the pilot reversible:

- Prefer: subsidy Research notes for subsidy queries
- Prefer: Judgment Assets for judgment/screening queries
- Prefer: residual/useful-life terms for re-lease and resale queries
- Bury: chat logs, improvement logs, debug/Cloud Run operational notes

The debug endpoint also accepts `filter_expression` and `boost_spec` for
Discovery Engine API experiments.

### Google Search grounding status

Search API and Answer API are verified with the current gcloud token.

Google Search grounding code is present via Vertex AI REST and SDK fallback, but
the local verification currently returns:

- REST: read timeout
- SDK: `invalid_grant`

Use only after local/Cloud Run Vertex authentication is corrected and after
confirming the incremental grounding cost is acceptable.
