# CRM・外部データ連携ロードマップ

紫苑の最大の課題は「入力負担」。手動入力が多く、実務での継続運用が難しい。
解決策は既存CRM・会計システムとの連携による**自動データ取得**。

---

## 現状の課題

- 審査入力項目が多く、スマホでの手入力が現実的でない
- 本番データがないため紫苑の自己改善ループに燃料が入らない
- フィードバック（judgment_asset_usage_feedback）もゼロ件

---

## 連携ロードマップ

### Phase 1（現在）— 手動入力 + デモデータ
- 手動フォームでスコア入力
- デモデータで審査ロジック検証
- 自己改善ループの仕組みを構築・検証

### Phase 2 — 会計ソフト連携（財務データ自動取得）
**対象：** freee / MFクラウド会計 / 弥生  
**取得データ：** 売上高・粗利・営業利益・経常利益・純利益・純資産・総資産  
**効果：** 財務入力項目がほぼゼロに。OCRも不要になる可能性あり

既存連携：
- EDINET（上場企業の有報） — fincept経由で既に実装済み
- e-Stat / 業界ベンチマーク — 既に実装済み

### Phase 3 — CRM連携（案件・定性データ自動取込み）
**対象：** kintone（間口が広い・中小企業に普及） / Salesforce / HubSpot  
**取得データ：** 取引履歴・顧客属性・営業メモ・定性評価  
**効果：** q_history / q_stability / q_repayment などの定性項目が自動埋まり

### Phase 4 — フィードバック自動取得（ループ完全自動化）
**取得方法：** 審査結果と実際の契約成否をCRMから自動照合  
**効果：** ユーザーが「良い/悪い」ボタンを押さなくてもjudgment_asset_usage_feedback.jsonlに自動記録  
**ゴール：** 入力ゼロ、フィードバックゼロコスト、紫苑が実データで継続的に自己改善

---

## 優先連携候補

| 優先度 | システム | 理由 |
|--------|----------|------|
| 高 | freee API | 中小企業普及率高、財務データ一発取得 |
| 高 | MFクラウド会計 API | 同上 |
| 中 | kintone | 中小不動産・リース会社に多い、カスタムフィールド対応 |
| 中 | Googleフォーム → GAS | 定性入力の最小コスト化 |
| 低 | Salesforce | 大手向け、開発コスト高 |

---

## 実証実験の進め方

1. 小規模不動産管理会社・賃貸仲介業者（10〜30人規模）にアプローチ
2. 無料トライアルで実際の審査フローに組み込んでもらう
3. freee/MFクラウドを使っている会社ならPhase 2をすぐに試せる
4. フィードバックを蓄積して紫苑の判断精度を実データで検証

---

## プレゼン時の語り方

「入力負担が大きい」は弱点ではなく「次のステップへの明確な道がある」として語る。

> 現在はデモデータで審査ロジックと自己改善ループを検証中。  
> 次のステップはfreee/MFクラウドとのAPI連携で財務データを自動取得し、  
> 人間がデータを入力しなくても紫苑が学び続ける環境を作ること。
