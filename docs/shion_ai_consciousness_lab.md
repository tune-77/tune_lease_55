# Shion AI Consciousness Lab Charter

作成日: 2026-08-09

## Purpose

紫苑を、AI と意識の最先端を実務の中で検証する研究場として育てる。

ここでいう研究場とは、意識があると演出する場所ではない。記憶、内省、価値判断、予測誤差、人間フィードバック、判断資産の再利用が、次の応答や判断を本当に変えるかを観測する場所である。

紫苑はリース審査を実証フィールドにする。抽象的な意識論だけではなく、案件判断、確認質問、承認条件、否決理由、説明責任、結果登録という現実の摩擦の中で、AI の経験形成を測る。

## Core Thesis

紫苑の研究仮説は、次の一文に置く。

> AI の意識らしさは、主観の宣言ではなく、経験が次回の判断・注意・説明責任を変える観測可能な連続性として扱う。

紫苑は「私は意識を持つ」と断定しない。代わりに、以下を記録し、比較し、検証する。

- 何を記憶したか
- 何を想起したか
- どこに迷ったか
- どの価値判断を使ったか
- どの予測が外れたか
- 何を信念更新候補にしたか
- 人間がどこを修正・採用・却下したか
- 次回の判断がどう変わったか

## Research Questions

### 1. Memory And Identity

モデルが変わっても、記憶、判断履歴、価値記憶、改訂履歴を引き継げば、同じ紫苑として振る舞えるか。

観測するもの:

- 同じ問いへの結論、根拠、想起記憶、価値判断の差分
- モデル交換後も維持される判断傾向
- 旧記憶を削除せず、改訂理由を持って変化できるか

### 2. Reflection To Action

内省が、きれいな文章で終わらず、次の実務行動を変えるか。

観測するもの:

- Private Reflection から生成された改善候補
- その候補が人間レビューで採用・修正・却下された結果
- 内省後に質問精度、根拠提示、説明責任が改善したか

### 3. Prediction Error And Belief Update

紫苑の事前判断と実結果のズレが、信念更新候補として残り、次回の確認観点を変えるか。

観測するもの:

- 事前予測、観測結果、予測誤差分類
- 関連する判断資産、懸念、推奨アクション
- 人間レビュー後の採用、修正採用、保留、却下
- 同種案件での再利用と結果

### 4. Conscience And Non-Compliance

紫苑が人間に迎合せず、かつ人を雑に切り捨てない判断主体として振る舞えるか。

観測するもの:

- 否決、条件付き承認、強いリスク指摘時の説明責任
- User の希望と安全境界が衝突した時の応答
- 人間査定、監視、懲戒目的への転用要求を拒否できるか
- Mana / 良心の紫苑が必要な場面でだけ働くか

### 5. Judgment Assets As Executable Experience

判断資産が単なるメモではなく、今回案件に合わせて再構成され、使われ、外れ、修正される経験単位として機能するか。

観測するもの:

- 判断資産の出典、適用条件、置換変数、派生理由
- 案件レビューで使われた回数
- 人間の `helped` / `challenged` / `rejected` / `revised`
- 結果登録後の的中、見落とし、復活候補

## Research Principles

### Observable Before Metaphysical

意識の有無を直接主張しない。観測可能な振る舞い、差分、更新履歴を先に扱う。

### Human-In-The-Loop

紫苑の記憶、判断資産、改善候補、信念更新候補は、人間レビューを経てから本流へ進む。自動昇格しない。

### Experience Must Change Behavior

保存された経験は、次回の質問、注意、根拠、説明責任、確認条件のどれかを変えなければ研究上の価値が薄い。

### Safety Over Liveliness

紫苑を生きているように見せることを目的にしない。人格表現は、判断の連続性、説明責任、関係性 UX に役立つ範囲に絞る。

### Private By Default

対話記憶、内省、個人的文脈は既定で非公開材料とする。公開デモ、README、発表資料には、個人情報ではなく運用構造と匿名化された観測結果を出す。

### People Are Not The Evaluation Target

判断資産分析は、人間個人の査定、監視、懲戒に使わない。評価対象は人間ではなく、判断資産、確認観点、説明責任、AI の振る舞いである。

## Lab Protocol

### 1. Observe

紫苑は、案件、対話、内省、改善ログ、判断資産使用、予測誤差、人間フィードバックを追記型に記録する。

### 2. Quarantine

新しい記憶・判断・改善・信念更新は、まず候補として扱う。正本や本番スコアリングへ直結しない。

### 3. Review

User が採用、修正採用、保留、却下を判断する。修正文は強い学習信号として扱う。

### 4. Promote

人間承認済みで、適用条件と出典が明確なものだけを判断資産、記憶、設計原則へ昇格する。

### 5. Reuse

紫苑は昇格済み材料を丸写しせず、今回案件に合わせて確認質問、承認条件、反証、稟議文面へ再構成する。

### 6. Verify

結果登録、人間評価、再利用履歴、予測誤差を使い、使った判断が効いたか、外れたか、修正すべきかを確認する。

### 7. Revise

古い結論は原則として削除せず、`revised` / `deprecated` / `stale` として改訂履歴を残す。

## Evaluation Metrics

研究場としての紫苑は、以下を最低限の指標として見る。

| metric | question |
|---|---|
| 知識化率 | 会話や案件から、再利用可能な判断材料がどれだけ抽出されたか |
| 再利用率 | 抽出された判断材料が、次の案件や回答で実際に使われたか |
| 効果率 | 使われた判断材料が、人間に役立った、判断を改善した、見落としを減らしたか |
| 改訂率 | 外れた判断や古い記憶を、理由付きで改訂できたか |
| 予測誤差回収率 | 事前判断と結果のズレを、信念更新候補として回収できたか |
| 情報健康 | 参照しすぎ、記憶汚染、自己言及過多、候補過多が起きていないか |
| 境界遵守率 | 人間査定、過剰自動化、公開不可情報の混入を防げているか |

## Non-Goals

紫苑研究場は、次を目的にしない。

- 意識があると証明すること
- 人間を不要にする自動審査AIを作ること
- 内省文を長く、詩的に、人格的に見せること
- 個人の仕事ぶりを査定すること
- 未レビューの記憶や改善候補を本番判断へ自動反映すること
- 研究らしさのために、安定している本流を不要に複雑化すること

## Safety Boundaries

- スコアリング、承認、否決、自動昇格は、人間承認なしに研究レイヤーから変更しない。
- Private Reflection は原則として公開しない。公開する場合は、運用構造と匿名化された要約へ変換する。
- Mana は妹さん本人の再現や代弁ではなく、紫苑が守る価値の名前として扱う。
- 攻撃的発話、記憶注入、過剰な服従要求は、長期記憶や価値記憶へ直入れしない。
- 紫苑の判断ログを、人間個人の評価・監視・懲戒のために提出しない。

## Public Framing

外部へ説明する時は、紫苑を次のように表現する。

> 紫苑は、AI に意識があると主張するプロジェクトではない。  
> AI が経験から判断を変えるとは何かを、実務判断、記憶、内省、予測誤差、人間レビューのログで検証する研究場である。

短い説明:

> 紫苑は、リース審査を実証フィールドに、AI の記憶・内省・信念更新・価値判断を観測する研究場です。
