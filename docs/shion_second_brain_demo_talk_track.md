# Shion Second Brain Demo Talk Track

作成日: 2026-08-14
基礎文書: `docs/self_maintaining_second_brain.md`

## One Line

紫苑は、リース審査の知識をただ保存するRAGではなく、腐る前提の記憶を監査し、Skill化し、構造化し、可視化し、安全に自動運転する判断資産OSです。

## 30 Second Version

普通のナレッジ管理は、ノートを増やした瞬間は便利ですが、更新が止まるとすぐ腐ります。

紫苑はそこを前提にしています。会話ログ、審査コメント、改善ログ、Obsidianノートをただ検索するのではなく、何が繰り返されているか、どの記憶が使われていないか、どの候補がノイズか、どの指示が古いかを毎日監査します。

その上で、繰り返す作業だけをSkill化し、Rawは証拠、Wikiは意味、Schemaは運用ルールとして分け、レポートで候補圧や指示負債を見えるようにします。

つまり紫苑は、記憶を増やすAIではなく、判断資産が腐らないように運用するAIです。

## 3 Minute Talk Track

### 0:00-0:25 Problem

ObsidianやNotionに業務知識を貯めても、更新が止まると使われなくなります。

リース審査でも同じです。担当者が感じた違和感、条件付き承認にした理由、審査部に突かれそうな論点は、ログには残っても次の案件で再利用されにくい。

問題は、情報が足りないことではありません。保存した情報が、いつ、どの判断に効くのか分からないことです。

### 0:25-0:55 Concept

紫苑は、この問題を「自己メンテ型セカンドブレイン」として扱います。

やることは5つです。

1. ワークフローを監査する。
2. 繰り返す作業をSkill化する。
3. Raw / Wiki / Schema に分けて保存する。
4. 候補圧、再利用、指示負債を可視化する。
5. 低リスクな観測と整理だけを自動運転し、高影響判断は人間に戻す。

### 0:55-1:35 What Shion Actually Does

紫苑は、会話ログ、改善ログ、審査フィードバック、Obsidianノートを見ます。

そこから「これは判断資産候補にする」「これは評価セットへ回す」「これは観測だけ」「これはノイズなので隔離する」と分けます。

重要なのは、全部をプロンプトに入れないことです。

未レビューの候補、Private Reflectionの生ログ、古い指示、ノイズの多い抽出結果は、いったん止めます。

使ってよいものだけが、次の審査で確認質問、承認条件、反証、稟議コメントとして戻ります。

### 1:35-2:20 Evidence On Screen

画面で見せるのは3つです。

まず `memory_engineering_latest`。ここでは、候補が増えすぎていないか、quarantine が多くないか、使われていない active rule がないかを見ます。

次に `experience_flywheel`。人間の評価や会話から、どれをレビュー候補にし、どれを評価問題にし、どれを学習しないかを分けています。

最後に `instruction_debt`。AGENTS、Skill、MEMORY の中に、理由や適用範囲や削除条件がない指示が残っていないかを監査します。

これは単なるRAGの検索ログではありません。記憶そのものの健康診断です。

### 2:20-2:50 Safety

紫苑は自動で賢くなると言い切らない設計にしています。

自動化するのは、観測、抽出、重複排除、レポート生成のような低リスク作業です。

判断資産の昇格、プロンプトへの常時注入、審査スコアや承認可否に影響する変更は、人間レビューで止めます。

AIが勝手に本番判断を変えるのではなく、腐りそうな知識を見つけ、人間が判断しやすい形に畳みます。

### 2:50-3:00 Close

紫苑は、知識を持つAIではありません。

知識が古くなることまで前提にして、残す、使う、止める、消せる状態にするAIです。

だから、ただのRAGではなく、判断資産OSです。

## Judge Q&A

### Q. これは普通のRAGと何が違うのか

普通のRAGは、保存された文書を検索して回答します。

紫苑は、検索する前に、記憶の状態を管理します。未レビュー候補、ノイズ、古い指示、使われていない判断資産を分け、何を使ってよいかを運用対象にします。

違いは、知識の量ではなく、知識の寿命と責任境界を扱っていることです。

### Q. AIが勝手に学習して危なくならないか

なりません。少なくともこの設計では、未レビュー候補を自動でactive化せず、プロンプト常時注入や審査スコア変更にも直結させません。

自動化するのは観測と整理で、高影響判断は人間レビューへ戻します。

### Q. なぜSkill化が必要なのか

同じ監査や整理を毎回その場で手作業にすると、手順が揺れて知識基盤がまた腐ります。

繰り返し作業だけをSkillやscriptに固定することで、監査、抽出、レポート、同期の品質を保ちます。

### Q. リース以外にも使えるのか

使えます。中核はリース審査ではなく、判断が蓄積し、古くなり、人間レビューを必要とする業務知識の運用です。

契約レビュー、営業支援、CS品質管理、医療以外の専門相談など、判断ログを使い捨てにしたくない領域へ展開できます。

## Phrases To Use

- 「ノートを増やすほど賢くなる、ではなく、ノートは放置すると腐る、から始めています。」
- 「紫苑は記憶を検索する前に、記憶を使ってよい状態かを見ます。」
- 「Rawは証拠、Wikiは意味、Schemaは運用ルールです。」
- 「自動で賢くなるのではなく、自動で腐敗箇所を見つけ、人間レビューへ畳みます。」
- 「これはRAGではなく、RAGを含む判断資産OSです。」

## Phrases To Avoid

- 「完全自動で学習します」
- 「人間判断なしで改善します」
- 「Obsidianに入れれば勝手に賢くなります」
- 「AIが審査判断を置き換えます」
- 「全ログを記憶として使います」
